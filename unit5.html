Q1 🔥 MUST DO★★★☆☆ 2 / 10 marksPYQ 2025 C5PYQ 2024 A107CAI 2025 A3
Discuss Autoencoders, their types and their applications in anomaly detection with examples.
📝 Exam answer

Definition: An autoencoder (AE) is an unsupervised neural network trained to copy its input to its output through a narrow or constrained hidden layer. Because it can't simply copy, it is forced to learn the most important features of the data. The input itself acts as the label (self-supervised).

Architecture (3 parts)

  • Encoder compresses the input into a code: h = f(x) = σ(W x + b)
  • Code / latent / bottleneck layer h holds the compressed representation.
  • Decoder rebuilds the input from the code: r = g(h) = σ(W′ h + b′)
Training objective: minimise L(x, g(f(x))), e.g. MSE = ‖x − r‖² (or binary cross-entropy for 0–1 pixels)

It is trained with backpropagation + gradient descent, just like an MLP, except the target is x itself.

Types of autoencoders

TypeKey ideaUse
UndercompleteCode dim < input dim (bottleneck)Compression, dimensionality reduction
SparsePenalty makes most hidden units ≈ 0Feature learning
Denoising (DAE)Input noisy x̃, target clean xImage/audio denoising
Contractive (CAE)Penalise ‖∂h/∂x‖², robust to small changesRobust features
Variational / Stochastic (VAE)Encoder outputs a distribution (μ, σ), then we sampleGenerating new data
ConvolutionalConv layers in encoder, deconv in decoderImages

Application: anomaly detection

Idea: an AE trained only on normal data reconstructs normal samples well (low error) but reconstructs unusual samples badly (high reconstruction error).

  1. Collect normal data only (e.g. genuine transactions, healthy machine readings).
  2. Train the AE to reconstruct it (minimise MSE).
  3. Compute the reconstruction error on normal validation data and set a threshold: e.g. mean + 3σ, or the 95th/99th percentile.
  4. For a new sample: error = ‖x − r‖². If error > threshold, flag it as an anomaly.
Machine-sensor example (numbers)
Normal-data reconstruction errors: mean μ = 0.02, std σ = 0.01
Threshold = μ + 3σ = 0.02 + 0.03 = 0.05

New reading A: error = 0.03  → 0.03 < 0.05 → NORMAL ✔
New reading B: error = 0.18  → 0.18 > 0.05 → ANOMALY ⚠ (bearing fault?)

Credit-card fraud: AE trained on genuine transactions (amount, time, location…).
A ₹95,000 purchase at 3 AM in another country → reconstruction error 0.40 ≫ 0.05 → FRAUD alert.

Why it works: it needs no labelled fraud examples (fraud is rare), it learns "what normal looks like", and it handles high-dimensional data.

Other applications

  • Dimensionality reduction / compression
  • Image denoising
  • Feature extraction / pre-training
  • Generating new images (VAE)
  • Recommendation systems, missing-value imputation

Pipe patli hai, isliye sirf important cheezein hi guzarti hain. Anomaly detection: machine ko sirf normal data dikhao. Jab kuch ajeeb aata hai, woh usko theek se copy nahi kar paati, error bada aata hai, aur woh case "suspicious" ban jaata hai.

A teacher who has only ever read your handwriting can rewrite your notes from memory easily. If someone else writes in your notebook, the teacher struggles to reproduce it. That "struggle" (high error) reveals the stranger: anomaly detected.

Q2 🔥 MUST DO★★★☆☆ 4 / 10 marks7CAI 2025 C5
What is an Undercomplete Autoencoder? How does it prevent the network from learning an identity function?
📝 Exam answer

Definition: An autoencoder whose code dimension is smaller than the input dimension (dim h < dim x) is called undercomplete. The narrow middle layer is the bottleneck.

The identity-function problem: if the hidden layer were as large as the input (or larger: overcomplete), the network could just learn g(f(x)) = x by copying each value through. The loss becomes 0, but it learns nothing useful.

How undercomplete AE prevents it

  1. Bottleneck: e.g. 784 pixels must pass through only 32 numbers. Copying 784 values into 32 slots is impossible, so the network must compress.
  2. To keep the reconstruction error low, it keeps only the most salient features (shape of the digit, stroke) and drops noise and redundancy.
  3. The loss L(x, g(f(x))) drives it to capture the main factors of variation.

Relation to PCA

If the decoder is linear and the loss is MSE, an undercomplete AE learns the same subspace as PCA. With non-linear encoder/decoder it becomes a more powerful, non-linear generalisation of PCA.

⚠ Caution

If the encoder and decoder have too much capacity (very deep, huge), even a 1-D code can memorise the training set (e.g. map each sample to an index) and copy without learning useful features. So we keep the capacity moderate or add regularisation (Q3).

💜 Hinglish samjho

Agar beech ki layer input jitni badi ho, toh network "copy-paste" karke 100% marks le lega par kuch seekhega nahi (identity function). Undercomplete mein beech ki layer chhoti hai: 784 cheezein sirf 32 dabbon mein bharni hain. Isliye usko summary banana seekhna padta hai. Linear + MSE ho toh yeh PCA ban jaata hai.

🟢 Easy example (English)

Your teacher says "summarise this 10-page chapter in 5 lines". You can't copy it word for word, so you must pick the key points. If you were allowed 10 pages, you would just copy and learn nothing. The 5-line limit is the bottleneck.

🌸 आसान उदाहरण (हिंदी)

10 पेज का अध्याय सिर्फ़ 5 लाइनों में लिखना है। हूबहू नकल संभव नहीं, इसलिए मुख्य बातें ही चुननी पड़ेंगी। अगर 10 पेज लिखने की छूट होती, तो आप बस नकल कर देते और कुछ नहीं सीखते — यही identity function की समस्या है।

💡 Exam tip

Write the key line: "dim(h) < dim(x) forces compression, so the AE cannot copy and learns the salient features." Then add "linear decoder + MSE = PCA" and the capacity caution. That combination scores full marks.

Q3 🔥 MUST DO★★★☆☆ 2 / 4 / 10 marksPYQ 2025 A107CAI 2025 B57CAI 2025 A7
What are Regularized Autoencoders? What is their purpose? Differentiate undercomplete vs regularized and regularized vs stochastic autoencoders.
📝 Exam answer

Definition: A regularized autoencoder adds a penalty term Ω to the reconstruction loss. The penalty forces useful properties on the code. It works even when the code is as large as or larger than the input (overcomplete).

L = L(x, g(f(x))) + λ · Ω(h, x)

Purpose (7CAI A7): to stop the AE from just copying the input (the identity function) and to learn sparse, robust, meaningful features that generalise well, without having to shrink the code size.

Main types

  1. Sparse AE: Ω = λ Σ|hᵢ| (L1) or a KL-divergence penalty KL(ρ ‖ ρ̂ⱼ) pushing the average activation ρ̂ⱼ towards a small ρ (e.g. 0.05). Only a few neurons fire for each input, like specialist "detectors".
  2. Denoising AE (DAE): corrupt the input x → x̃ (Gaussian noise or randomly zeroed pixels), then train to reconstruct the clean x: minimise L(x, g(f(x̃))). It must learn the structure of the data to remove the noise.
  3. Contractive AE (CAE): Ω = λ‖∂f(x)/∂x‖²F, which makes the code insensitive to small input changes (Q6).

💜 Hinglish samjho

Undercomplete mein "pipe patli" karke copy rokte hain. Regularized mein pipe badi ho sakti hai, par loss mein ek "saza" (penalty) jod dete hain. Sparse = "kam neurons jalao", Denoising = "gandi photo do, saaf wapas banao", Contractive = "chhote badlaav pe code mat hilao". Stochastic = output fix nahi, ek probability distribution hai, isliye naya data bhi bana sakta hai.

🟢 Easy example (English)

Denoising: a scratched old photo goes in and a clean photo comes out. To remove the scratches, the network must understand what faces normally look like. Sparse: in a big office, only the 2–3 relevant experts answer each question, not everyone.

🌸 आसान उदाहरण (हिंदी)

पुरानी खरोंच वाली फ़ोटो डालो और साफ़ फ़ोटो निकालो — यह denoising AE है। खरोंच हटाने के लिए उसे समझना पड़ता है कि चेहरा असल में कैसा दिखता है। Sparse AE: बड़े दफ़्तर में हर सवाल का जवाब सिर्फ़ 2–3 विशेषज्ञ देते हैं, सब नहीं।

💡 Exam tip

Both tables are ready-made 4-mark answers. For the 2-mark A10: "Regularized AE is deterministic and adds a penalty (sparsity/noise/Jacobian) to the loss; stochastic AE uses probabilistic encoder/decoder p(h|x), p(x|h) and can generate new data (e.g. VAE)."

Q4 🔥 MUST DO★★★☆☆ 4 / 10 marksPYQ 2025 B7
Design a simple autoencoder for dimensionality reduction and explain its components.
📝 Exam answer

Task: reduce MNIST handwritten-digit images (28×28 = 784 pixels) to a 32-dimensional code, a 24.5× compression.

PartLayerNeuronsActivationParameters (W + b)
InputFlattened image784— (pixels scaled 0–1)0
EncoderDense 1128ReLU784×128 + 128 = 100,480
Dense 2 = Code32ReLU128×32 + 32 = 4,128
DecoderDense 3128ReLU32×128 + 128 = 4,224
Output784Sigmoid (0–1 pixels)128×784 + 784 = 101,136
Total trainable parameters209,968
  • Loss: MSE ‖x − r‖² or binary cross-entropy (pixels in 0–1).
  • Optimiser: Adam, learning rate 0.001, batch size 256, about 20–50 epochs.
  • Training data: X is both the input and the target (no labels needed).

Components explained

  1. Encoder (784→128→32) progressively compresses the image and extracts features.
  2. Bottleneck / code (32) is the reduced representation. This is the output we use for dimensionality reduction.
  3. Decoder (32→128→784) mirrors the encoder and reconstructs the image, which forces the code to keep the important information.
  4. Loss function measures reconstruction quality; backpropagation + Adam train all the weights.

After training: throw away the decoder. Use encoder(x) to get 32 features for visualisation, clustering or a faster classifier. Advantage over PCA: it captures non-linear structure.

# Keras sketch (optional)
inp = Input(784)
h   = Dense(128, 'relu')(inp)
code= Dense(32,  'relu')(h)
h2  = Dense(128, 'relu')(code)
out = Dense(784, 'sigmoid')(h2)
ae  = Model(inp, out); ae.compile('adam', 'mse'); ae.fit(X, X, epochs=30)
encoder = Model(inp, code)   # dimensionality reducer
💜 Hinglish samjho

784 pixels ko 32 numbers mein dabaana hai. Encoder 784→128→32 (chhota karta jaata hai), decoder 32→128→784 (wapas bada karta hai). Training mein input hi target hai. Training ke baad decoder hata do; encoder hi tumhara "dimension reducer" hai. Parameters ≈ 2.1 lakh.

🟢 Easy example (English)

Zipping a file: a 784 KB photo is zipped to 32 KB (encoder) and unzipped back (decoder). If the unzipped photo looks like the original, the zip kept everything important.

🌸 आसान उदाहरण (हिंदी)

बड़ी फ़ाइल को ZIP करना (encoder) और फिर UNZIP करना (decoder)। अगर खोलने पर फ़ाइल लगभग वैसी ही मिले, तो ZIP ने ज़रूरी जानकारी बचा ली। छोटी ZIP फ़ाइल ही "कम आयाम वाला कोड" है।

💡 Exam tip

"Design" means a layer table + loss + optimiser + diagram + a "why" line for each part. The parameter count is a bonus that impresses examiners. Mention that the encoder is symmetric to the decoder.

Q5 ⭐ HIGH★★★★☆ 4 / 10 marks
Explain Stochastic Encoders and Decoders. How are they related to the Variational Autoencoder?
📝 Exam answer

In a normal AE, the encoder and decoder are deterministic functions. In a stochastic AE, they are generalised to probability distributions:

Stochastic encoder: pencoder(h | x) = pmodel(h | x)
Stochastic decoder: pdecoder(x | h) = pmodel(x | h)
  • The decoder outputs the parameters of a distribution over x. For real-valued x it outputs a Gaussian mean (so the loss becomes MSE); for binary x it outputs Bernoulli probabilities via sigmoid (so the loss becomes cross-entropy).
  • Training minimises the negative log-likelihood: L = −log pdecoder(x | h). This links to MLE (Unit 1).
  • Noise is injected in the encoder, so the same x can give slightly different h. This makes the model robust and able to generate data.

Variational Autoencoder (VAE), the most famous stochastic AE

  1. The encoder outputs a mean μ and standard deviation σ for each latent dimension, instead of a single point.
  2. Reparameterisation trick: z = μ + σ · ε, ε ~ N(0, 1). This lets gradients flow through the random sampling.
  3. The decoder reconstructs x from z.
  4. Loss = reconstruction loss + KL( q(z|x) ‖ N(0, I) ). The KL term keeps the latent space smooth and close to a standard normal.
  5. Generation: sample z ~ N(0, I) and pass it through the decoder to get a brand-new image.
💜 Hinglish samjho

Normal AE ek fixed point pe code rakhta hai. Stochastic AE kehta hai "code ek range hai, ek baadal (μ, σ)". Usme se random sample lo (z = μ + σε) aur decoder se image banao. Isliye har baar thoda alag aur naya output aata hai, yaani VAE naye chehre/digits generate kar sakta hai. Loss = copy ki galti + KL (cloud ko normal shape mein rakho).

🟢 Easy example (English)

A normal AE remembers "this face = point (2, 3)". A VAE remembers "this face ≈ somewhere around (2, 3) ± 0.5". Picking slightly different points in that area gives new but realistic faces, like the same person with a different smile.

🌸 आसान उदाहरण (हिंदी)

सामान्य AE: "यह चेहरा = बिंदु (2, 3)"। VAE: "यह चेहरा (2, 3) के आसपास ±0.5 के दायरे में है"। उस दायरे से अलग-अलग बिंदु चुनो तो नए पर असली जैसे चेहरे बनते हैं — एक ही व्यक्ति, अलग मुस्कान।

💡 Exam tip

Must-write formulas: pencoder(h|x), pdecoder(x|h), L = −log pdecoder(x|h), z = μ + σ·ε, and the KL term. Five formulas plus the diagram make a strong 10-mark answer.

Q6 ⭐ HIGH★★★★☆ 2 / 4 marks
Explain the Contractive Autoencoder (CAE). How does it differ from a Denoising Autoencoder?
📝 Exam answer

A Contractive Autoencoder is a regularized AE that adds a penalty on the Jacobian of the encoder, i.e. how much the code h changes when the input x changes a little.

L = L(x, g(f(x))) + λ · ‖ ∂f(x)/∂x ‖²F
‖J‖²F = Σᵢ Σⱼ ( ∂hⱼ / ∂xᵢ )² (squared Frobenius norm = sum of squares of all partial derivatives)
  • Intuition: the penalty makes the encoder "contract" a neighbourhood of inputs to a small neighbourhood of codes. Small, unimportant changes (noise, slight shifts) barely change h.
  • Balance: the reconstruction term wants h to change with x (to tell inputs apart), while the penalty wants h to stay still. Result: h is sensitive only along the directions where real data varies (the data manifold) and insensitive to other directions.
  • λ controls the trade-off: too large and everything maps to the same code; too small and it becomes a plain AE.
PointContractive AEDenoising AE
How robustness is achievedAnalytically: penalty on ‖∂h/∂x‖²Empirically: add noise to the input, reconstruct clean x
Robust partThe encoder / code hThe whole reconstruction g(f(x))
Noise needed?NoYes (corruption process)
CostJacobian computation (more expensive)Cheap
💜 Hinglish samjho

Contractive AE ko bolte hain: "input mein chhota sa badlaav ho (thoda noise, thoda shift), toh code mat hilao." Iske liye ∂h/∂x (h kitna badla) ko chhota rakhne ki penalty lagti hai. Denoising AE same kaam noise daal ke practically karta hai; contractive AE formula se karta hai.

🟢 Easy example (English)

You recognise your friend whether they wear glasses, a cap, or stand in dim light. Your "code" for the friend stays the same under small changes. That stability is what the contractive penalty teaches.

🌸 आसान उदाहरण (हिंदी)

आपका दोस्त चश्मा पहने, टोपी लगाए या कम रोशनी में खड़ा हो — आप फिर भी उसे पहचान लेते हैं। छोटे बदलावों से आपकी "पहचान" नहीं बदलती। यही स्थिरता contractive AE सिखाता है।

💡 Exam tip

The one formula to remember is λ‖∂f(x)/∂x‖²F, with the phrase "Frobenius norm of the Jacobian of the encoder". Add the CAE vs DAE table for 4 marks.

⚡ Part-A quick answers (2 marks, ~25 words each)

  1. What is an autoencoder? An unsupervised neural network that learns to reconstruct its input via encoder h = f(x) and decoder r = g(h), minimising L(x, g(f(x))). The code gives compressed features.
  2. Applications of autoencoders? Dimensionality reduction, image denoising, anomaly/fraud detection, feature learning and pre-training, data generation (VAE), recommendation systems. 2024 A10 7CAI A3
  3. Regularized vs stochastic autoencoder? Regularized: deterministic, adds a penalty (sparse/denoising/contractive) to the loss. Stochastic: probabilistic p(h|x), p(x|h), loss −log p(x|h), and can generate data (VAE). 2025 A10
  4. Purpose of a regularized autoencoder? To prevent copying the input (identity) even with a large code, and to learn sparse, robust, generalisable features through a penalty term. 7CAI A7
  5. Undercomplete autoencoder? An AE whose code dimension is smaller than the input dimension. The bottleneck forces it to learn the most salient features.
  6. Overcomplete autoencoder? Code dimension ≥ input dimension. Without regularisation it can learn the identity function, so it needs sparse/denoising/contractive penalties.
  7. Denoising autoencoder? Trained to reconstruct the clean x from a corrupted x̃: minimise L(x, g(f(x̃))). It learns robust features and removes noise.
  8. Sparse autoencoder? Adds an L1 or KL penalty on the hidden activations so only a few neurons are active for each input.
  9. Contractive autoencoder? Adds λ‖∂f(x)/∂x‖²F (Jacobian penalty) so the code is insensitive to small input changes.
  10. Reconstruction error? The difference between the input and the AE output, e.g. ‖x − r‖². A high error on a new sample indicates an anomaly.
  11. Autoencoder vs PCA? PCA is linear. An AE with a linear decoder + MSE equals PCA, but with non-linear layers it learns more powerful non-linear features.
  12. Reparameterisation trick? In a VAE, z = μ + σ·ε with ε ~ N(0,1). It moves the randomness outside the network so backpropagation can flow through μ and σ.
